Checkout API — Documentation

Turns a Webflow quote form into a Stripe deposit or an emailed quote, and keeps HubSpot up to date either way.

Overview How it works For developers API reference Support

Overview

This service sits behind your Webflow quote form. A customer builds a cart, then either:

  • Pays a deposit — redirected to a real Stripe Checkout session, itemized line by line, or
  • Requests the quote by email — no payment, the itemized quote is emailed immediately.

Either way, the lead is recorded in HubSpot as a Contact and Deal, with a plain-language note listing everything in the cart — so a salesperson never has to read raw data to understand what a customer wants.

How it works

1. Customer submits the form

Name, email, and cart are sent to this API. Each cart item has a name, quantity, and a price — or price: 0 for something that needs an in-person/site review before it can be priced (e.g. custom surfacing). Quote-only items are never charged, but they're never dropped either — they travel through every downstream view of the order.

2. Choosing deposit vs. email-only

Pay a deposit (POST /api/checkout)

A HubSpot Deal is created first, then only the priced items go to Stripe (there's nothing to charge for a $0 item). The customer is redirected to Stripe's hosted checkout and pays with a card.

Email me the quote (POST /api/quote/email)

A HubSpot Deal is created first, then the full cart — priced and quote-only items — is emailed immediately, itemized, with quote-only items clearly marked instead of showing a misleading "$0.00". No Stripe session at all.

The Deal is created before the email/checkout step specifically so its own id can be used as the customer's Order # — the same number shows up in the email and on the Deal, so a support call referencing "Order #12345" maps straight to that Deal.

3. What HubSpot sees

Every submission — deposit or email-only — creates or updates a Contact (by email) and a Deal, placed directly into a specific configured pipeline (e.g. "Sales Order Pipeline") rather than the account's default one, and tagged with a Deposit Status:

StatusMeaning
PendingSent to Stripe Checkout, payment not yet confirmed
PaidStripe confirmed the deposit
No DepositCustomer chose "email me the quote" — no payment involved
Failed / ExpiredThe Stripe session didn't complete

The Deal also gets a Note — not just a raw data field — leading with Order # and an Order Type line ("Deposit — awaiting Stripe Checkout" or "Email Quote Only — no deposit collected"), so a rep knows which route the customer chose at a glance, without opening anything else. Below that: every item, its price (or "price provided after review"), and the total.

4. After a deposit is paid

A branded receipt email goes out automatically, with the same Order # as the Deal. If the original cart mixed priced and quote-only items, the receipt shows two tables: what was actually paid for, and what still needs pricing — so nothing about the order is ambiguous to the customer.

For developers

Plain Node.js + Express (ESM), no database — Stripe Checkout Sessions and HubSpot Deals are the system of record. No build step, no frontend framework.

ConcernHandled by
PaymentsStripe Checkout Sessions
CRM / lead trackingHubSpot Contacts, Deals & Notes

FrontendPlain JS snippet pasted into Webflow (public/webflow-checkout.js) — no SPA

Full setup instructions (env vars, getting API keys, local development, deployment, troubleshooting) live in the repo's README.md — this page is a map, not a replacement for it.

API reference

Method & pathPurposeNotes
GET /healthLiveness checkReturns { ok: true }
POST /api/checkoutCreate a Stripe Checkout session for a deposit20 req / 15 min per IP
POST /api/quote/emailEmail the itemized quote, no payment5 req / 15 min per IP
POST /api/webhooks/stripeStripe-only — updates HubSpot & sends the receiptNot for manual calls; verified via Stripe-Signature

Both POST routes take the same body shape — name, email, and a JSON-encoded quoteItems string. See the README's endpoint sections for full request/response examples.

Support

Something look wrong with an order? Check the Deposit Status and the details Note on the HubSpot Deal first — between those two, most questions about what a customer ordered and whether they paid are answerable without touching the code.
